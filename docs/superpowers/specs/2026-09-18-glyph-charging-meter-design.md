# Glyph Charging Meter — дизайн

Дата: 2026-09-18
Статус: утверждён пользователем, готов к написанию плана реализации

## 1. Задача

Приложение для телефонов Nothing, которое во время зарядки показывает уровень
заряда на Glyph-интерфейсе и проигрывает анимацию при подключении питания.

Целевые устройства первой версии: Phone (3a) и Phone (3a) Pro (в SDK это одно
устройство, `Glyph.DEVICE_24111`). Остальные модели поддерживаются архитектурно
через таблицу раскладок, но на железе не проверяются.

Распространение: open source на GitHub, APK в releases.

### Зачем это нужно

На Phone (3a) и (3a) Pro встроенного индикатора заряда (Charging meter) нет —
Nothing не перенесла эту функцию с Phone (1)/(2). Подтверждено ответом
разработчика GlyphNexus на nothing.community (d/43963), жалобами пользователей
(d/32523, d/29900) и составом раздела Glyph Interface в руководстве 3a Pro.

## 2. Установленные факты о SDK

Источник: https://github.com/Nothing-Developer-Programme/Glyph-Developer-Kit
(README + анализ байткода `sdk/glyph-matrix-sdk-2.0.aar`, пакет
`com.nothing.ketchum`). Проверено 2026-09-18.

- Артефакт распространяется только как локальный `.aar`, Maven-координат нет.
  `minSdkVersion` в манифесте aar — 33.
- Один и тот же aar обслуживает и полосковые глифы (`GlyphManager`), и матричные
  (`GlyphMatrixManager`, Phone (3) и 4a Pro). Для целевых устройств нужен только
  `GlyphManager`.
- Устройства: Phone (1) `DEVICE_20111`, (2) `22111`, (2a) `23111`,
  (2a) Plus `23113`, (3a) и (3a) Pro `24111`, (4a) `25111`, (4b) `25131`.
- Раскладка `DEVICE_24111`: 36 адресуемых сегментов.

  | Зона | Константы | Индексы | Порядок |
  |---|---|---|---|
  | A | `A_1`…`A_11` (11 шт.) | 20–30 | A_1 верх → A_11 низ |
  | B | `B_1`…`B_5` (5 шт.) | 31–35 | B_1 нижний правый → B_5 верхний левый |
  | C | `C_1`…`C_20` (20 шт.) | 0–19 | C_1 нижний левый → C_20 верхний правый |

- Жизненный цикл: `GlyphManager.getInstance(ctx)` → `init(callback)` → в
  `onServiceConnected` вызвать `register(deviceId)` → `openSession()`. На
  завершении — `closeSession()` и `unInit()`.
- Методы вывода: `toggle(frame)`, `animate(frame)`, `displayProgress(frame,
  progress[, reverse])`, `displayProgressAndToggle(...)`, `turnOff()`.
- `displayProgress` на `DEVICE_24111` принимает кадр с одним из каналов `A_1`,
  `B_1`, `C_1` и заполняет соответствующую зону целиком, шагами по сегменту.
- `GlyphFrame.Builder` имеет недокументированную перегрузку
  `buildChannel(channel, light)` — индивидуальная яркость сегмента.
  Константы `GlyphManager`: `DEFAULT_MAX_LIGHT` = 4096, `DEFAULT_MIN_LIGHT` = 800,
  `NO_LIGHT` = 0. Фактический диапазон 0–4095.
- Ограничение максимальной длительности сессии в SDK не обнаружено (таймаут
  существует только у матричного API).

### Требования среды

- Манифест: `<uses-permission android:name="com.nothing.ketchum.permission.ENABLE"/>`
  и `<meta-data android:name="NothingKey" android:value="test"/>`.
- Начиная с Android 16 / Nothing OS 4.0 ключ разработчика не требуется (README).
- На Android 14 и 15 без ключа нужен Glyph Debug Mode: глобальная настройка
  `nt_glyph_interface_debug_enable` = 1. Сбрасывается автоматически через 48 часов.
- README заявляет «only foreground applications are allowed», однако открытый
  аналог NothingGlyphBattery работает из foreground service типа `specialUse`.
  Считаем foreground service рабочим подходом и проверяем на устройстве.

### Непроверенное

- Точная семантика аргумента `progress` у `displayProgress` (предположительно
  0–100, подтвердить на устройстве в первую очередь).
- Поведение без debug-режима и без ключа на Nothing OS 3.x.
- Наличие скрытого потолка длительности сессии.

## 3. Ключевая идея: настоящая плавность

Штатный `displayProgress` заполняет зону C шагами по сегменту, то есть даёт 20
ступеней — 5% заряда на ступень. Это заметно дёргается.

Вместо этого используем поканальную яркость. Уровень раскладывается так: целые
сегменты горят на полной яркости, а следующий за ними светится частично,
пропорционально дробному остатку. Уровень 63% на зоне из 20 сегментов — это 12
сегментов на полной яркости и 13-й на 60%. Шкала становится практически
непрерывной.

Второй, независимый слой плавности: при изменении уровня заряда шкала не
прыгает, а анимированно переходит к новому значению за ~500 мс по кривой
замедления.

Ни одно из найденных сторонних приложений (Glyphify, GlyphNexus, Glyph Sharge,
NothingGlyphBattery) дробного сегмента не делает.

## 4. Технологический стек

- Kotlin, Jetpack Compose, Material 3 (Expressive).
- Foreground service для отслеживания зарядки.
- Локальные настройки — DataStore.
- Тесты: JUnit для чистых слоёв (без Android), инструментальные — только для
  слоя железа и сервиса.

Обоснование Compose: пользователь просил интерфейс в духе современных
приложений Google; Material 3 Expressive — это ровно он.

## 5. Архитектура

Четыре слоя, каждый с узким интерфейсом и независимо тестируемый.

### 5.1 Слой железа (`glyph-hardware`)

Единственное место в проекте, знающее о `com.nothing.ketchum`.

Наружу отдаёт интерфейс примерно такой формы:

- `connect()` / `disconnect()` — жизненный цикл сессии;
- `render(frame: GlyphFrameData)` — отрисовать кадр;
- `turnOff()`.

`GlyphFrameData` — это массив яркостей по индексам сегментов (0..N-1),
значения 0..4095. Ни про зоны, ни про проценты заряда слой не знает.

Подменяется фейковой реализацией в тестах. Внутри содержит fallback: если
`buildChannel(channel, light)` бросает исключение (перегрузка исчезла в
обновлении Nothing OS), слой переключается на `displayProgress` и сообщает об
этом наверх через состояние.

### 5.2 Слой раскладки (`glyph-layout`)

Чистые функции, ноль зависимостей от Android.

- Описание модели телефона — данные, а не код: идентификатор устройства, общее
  число сегментов, зоны с их индексами, какая зона считается шкалой заряда.
  Добавление Phone (2a) — одна запись в таблице.
- `levelToFrame(level: Float, layout: DeviceLayout, brightness: Int):
  GlyphFrameData` — здесь живёт логика дробного сегмента.
- Отдельный вариант той же функции для ступенчатого fallback-режима.

Тестируется обычным JUnit, без эмулятора.

### 5.3 Слой анимации (`glyph-animation`)

Тоже чистый. Генерирует последовательность кадров как функцию от времени.

- Пресеты подключения: заполнение снизу вверх, волна по всем зонам, дыхание,
  бегущий огонь, вспышка. Пресет описывается данными (ключевые точки по зонам и
  времени), а не отдельным классом на каждый.
- Переход уровня: интерполяция между двумя значениями по кривой замедления.
- Плавное угасание при скрытии шкалы.

Время подаётся снаружи параметром, поэтому тесты не используют задержек.

### 5.4 Слой оркестрации (`charging-service`)

Foreground service. Знает про настройки и про события системы, не знает про
`com.nothing.ketchum`.

- Слушает подключение и отключение питания, различает проводную и беспроводную
  зарядку, отслеживает уровень заряда.
- Решает по настройкам, какой сценарий запустить.
- Собирает кадры из слоёв раскладки и анимации и отдаёт их слою железа.

## 6. Поведение

### 6.1 Режимы индикатора

Оба доступны с первой версии, выбираются в настройках.

**Постоянный.** Шкала горит всю зарядку, плавно растёт вместе с уровнем.
Настраиваемая яркость. Опция гашения, когда телефон лежит экраном вверх.

**По событию.** При подключении играет выбранный пресет анимации, затем шкала
держится заданное время и плавно гаснет. Показ повторяется при каждом приросте
на заданное число процентов.

### 6.2 Анимации

Разные наборы пресетов на проводную зарядку, беспроводную и достижение 100%.
Отключение питания — короткая анимация затухания. В приложении есть превью
каждого пресета на экране телефона и на самом глифе. На глифе превью играет,
когда приложение включено и есть доступ к глифу: интерфейс не трогает дисплей,
а отправляет запрос в шину `PreviewRequestBus`, которую разбирает оркестратор —
единственный владелец дисплея, на том же однопоточном диспетчере. Второго
писателя в SDK нет. Предпросмотр не подавляется настройкой гашения экраном
вверх и работает без зарядки; после него идёт возврат к шкале (если заряжается)
или погашение. Если сервис не запущен, на экране объясняется, что на глифе
превью видно только при включённом приложении; сервис ради превью не запускается.

Каждую из пяти выбираемых анимаций можно настроить отдельно (`AnimationParams`
в `:core:animation`, хранится в `GlyphSettings.animationParams` по id пресета):
длительность одного прохода 0,5–3 с, собственная яркость (пока её не трогали,
она следует яркости шкалы), число повторов 1–5, зоны (хотя бы одна остаётся
включённой), направление по или против часовой стрелки для волны и бегущего огня.
Порядок по часовой стрелке — порядок `DeviceLayout.zones` (на (3a): C, A, B).
Для заполнения дополнительно: цель — вся полоса или уровень заряда, стиль —
плавно или по сегментам. Заполнение до уровня заряда идёт только по зоне шкалы,
последний проход не гаснет, а заканчивается ровно тем кадром, который рисует
шкала (`PresetFrameSource.handoffLevel`), и оркестратор продолжает шкалу с этого
уровня без затемнения. Пресет без записи играет со значениями по умолчанию;
«Сбросить» удаляет запись. Затухание при отключении не настраивается.

### 6.3 Экраны

1. **Главный.** Переключатель работы, выбор режима, живое превью шкалы на
   экране, текущее состояние доступа к Glyph.
2. **Настройки.** Яркость, длительность показа, шаг повторного показа, выбор
   пресетов, гашение экраном вверх, переход к настройке каждой анимации.
4. **Настройка анимации.** Превью с кнопкой проигрывания на глифе, длительность,
   яркость, повторы, заполнение (для «Fill up»), зоны, направление (для волны и
   бегущего огня), сброс к значениям по умолчанию.
5. **Онбординг.** Определение модели, проверка доступа к Glyph, инструкция по
   выдаче доступа (см. раздел 7).

## 7. Подсистема доступа к Glyph

Отдельная подсистема, потому что от неё зависит, работает приложение или нет.

### 7.1 Три состояния

1. **Работает напрямую.** Nothing OS 4.0 и новее — ограничение снято, ничего
   делать не нужно. Проверяется первым, до показа любой инструкции.
2. **Управляется приложением.** Приложению выдано `WRITE_SECURE_SETTINGS`,
   поэтому оно само выставляет `nt_glyph_interface_debug_enable` при запуске и
   при загрузке телефона, в том числе после каждого истечения 48 часов.
3. **Нужна разовая настройка.** Показывается инструкция.

### 7.2 Основной путь настройки: разовая команда adb

Пользователь один раз с компьютера выдаёт разрешение:

```
adb shell pm grant <package> android.permission.WRITE_SECURE_SETTINGS
```

После этого приложение включает debug-режим само и навсегда. К компьютеру
пользователь больше не возвращается.

Это выбрано основным путём вместо прямой команды включения режима, потому что
прямая команда требует повторения каждые 48 часов.

### 7.3 Запасной путь: Shizuku

Для тех, у кого нет компьютера. Shizuku поднимается один раз через беспроводную
отладку прямо с телефона, приложение пишет флаг через него. Минус: после
перезагрузки телефона Shizuku нужно запускать заново.

Предлагается в онбординге вторым вариантом.

### 7.4 Диагностика

Приложение проверяет фактическое состояние флага и показывает понятное
объяснение, если Glyph перестал отвечать. Молчаливой поломки быть не должно.

## 8. Обработка ошибок

- Исчезновение недокументированной перегрузки `buildChannel` → автоматический
  переход на ступенчатый режим, уведомление пользователя о снижении плавности.
- Неподдерживаемое устройство → явный экран с объяснением, а не падение.
- Потеря сессии Glyph → переподключение с ограниченным числом попыток.
- Отсутствие доступа → состояние 3 из раздела 7.1, а не тишина.

## 9. Тестирование

- Слой раскладки и слой анимации — чистые JUnit-тесты: границы (0%, 100%),
  корректность дробного сегмента, монотонность шкалы, совпадение длины кадра с
  раскладкой устройства.
- Слой оркестрации — тесты на фейковом слое железа и подставленных событиях
  зарядки: правильный сценарий на подключение, повторный показ по шагу
  процентов, гашение по таймауту.
- Слой железа — инструментальные тесты и ручная проверка на Phone (3a).
- Тесты пишутся вертикальными срезами: один тест → одна реализация.

## 10. Границы первой версии

Входит: индикатор заряда в двух режимах, пресеты анимаций, три экрана,
подсистема доступа, поддержка 3a и 3a Pro, таблица раскладок под остальные
модели.

Не входит: редактор анимаций, импорт из Glyph Composer, уведомления и звонки на
глифе, статистика зарядок, виджет, ограничение зарядки до 80%,
предупреждение о низком заряде.
