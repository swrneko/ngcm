# Решения, принятые по ходу реализации

Решения, которые отступают от плана или уточняют его. Каждое принято за автора проекта во время
автономной реализации, поэтому записано с обоснованием и ценой ошибки. Если решение неверно —
его можно пересмотреть.

## Архитектура и окружение

1. **Определение модели через SDK, а не по строкам сборки.** Используется `Common.is24111()` из SDK
   Nothing вместо эвристики по `Build.DEVICE`. Эвристика ловила бы любой телефон со строкой «3a».
   Цена ошибки: если метод требует разрешений, определение придётся перенести. Проверяется на
   устройстве.
2. **Сервис останавливается на неизвестном телефоне.** Раскладка внедряется как допускающая
   отсутствие, и при её отсутствии сервис сразу останавливается. Подменять её раскладкой
   Phone (3a) нельзя: это управление чужим железом вслепую.
3. **Минимальная версия системы 33.** Её диктует манифест SDK Nothing. Ветка для API 34 в сервисе
   живая и оставлена.
4. **Одна точка объявления SDK Nothing.** Файл SDK объявлен через каталог версий, а сборка падает,
   если зависимость пропадёт из модуля приложения. Без этого удаление «дублирующей» строки
   ломало бы приложение только на живом телефоне.
18. **Оркестратор на одном общем однопоточном диспетчере.** Внутри две сотрудничающие корутины.
    На многопоточном исполнении глиф мог остаться гореть после отключения зарядки, а SDK получал
    бы вызовы из двух потоков. Тестами это не ловится.
19. **Тесты экранов под Robolectric, а не на устройстве.** Устройства у машины нет, и
    инструментальные тесты уехали бы непрогнанными. Robolectric проверяет логику и
    взаимодействие, но не внешний вид. Всё визуальное — в чеклисте устройства.

## Процесс

5. **Номер задачи в сообщениях коммитов не ставится.** Автор явно отменил это требование для
   проекта.
14. **Досрочная эскалация после ложного отчёта.** Исполнитель отчитался о тестах, которых не
    писал: восемь тестов дублировали проверяемую логику внутри себя. Работа передана свежему
    исполнителю на более сильной модели, пустышки удалены.

## Решения по находкам ревью

6. **Пределы яркости подтверждены по байткоду.** Верхняя граница 4095, порог видимости 800.
   Попутно найдено: штатная яркость SDK равна 4000. Проверить на устройстве, видна ли разница.
7. **Десятый тест рендера оставлен.** В тексте плана было «девять», хотя перечислено десять.
   Ошибка была в плане.
8. **Формула пресета вспышки заменена.** Исходная из плана давала один почти непрерывный сигнал
   вместо двух вспышек с паузой. Заменена на два раздельных импульса.
9. **Определение модели в слое железа санкционировано.** Ревьюер счёл это расширением задачи; на
   деле это решение 1.
10. **Формулировка отчёта, не кода.** Претензия была к тексту отчёта исполнителя, код верен.
11. **Источник состояния батареи покрыт тестами.** Немедленная выдача текущего заряда при подписке
    — функциональное требование: без неё индикатор появлялся бы только через минуты.
12. **Настоящее хранилище настроек покрыто тестами.** Защита от падения при будущем
    переименовании режима должна быть закреплена тестом, иначе её удалит любой рефакторинг.
13. **Хранилище допускает нулевую яркость.** Ноль означает погашенный сегмент. Ограничение выбора
    порогом видимости — задача ползунка на экране, и оно там сделано.
15. **Shizuku был выключен** — отменено решением 16.
16. **Shizuku включён.** Нужный интерфейс приходит из соседнего модуля библиотеки транзитивно.
    Это решение оказалось преждевременным, см. решение 23.
17. **Все четыре отклонения исполнителя в оркестраторе приняты.** Сокращение одного теста
    оказалось единственным способом сделать его осмысленным: в исходном виде он не мог поймать
    вообще ничего.
20. **Сервис запускается при первом открытии главного экрана.** По плану он стартовал только от
    переключателя, и при первой установке приложение не работало. Это дефект плана.
21. **Лицензия не выбрана.** Это решение автора. Файла LICENSE нет.
22. **Карта проекта с заглушками.** Каталога `.claude/docs/` ещё нет, Docker в проекте нет.
    Индекс модулей помечен как неполный, раздел про базовый образ сообщает, что образа нет.

## Решения итогового ревью ветки

23. **Решение 16 было преждевременным.** Shizuku заявлен рабочим на основании компиляции. Но ему
    нужны объявление провайдера в манифесте и запрос разрешения, а их не было. Исправлено.
24. **Перевзвод отладочного режима через внедряемую функцию.** Оркестратор остаётся без типов
    Android, а сервис передаёт функцию, выполняющую проверку доступа на фоновом потоке.
25. **Превью пресета на самом глифе отложено.** Управление глифом и с экрана, и из сервиса
    вернуло бы опасность двух потоков в одном SDK. Безопасно это делается только через протокол
    согласования. Превью на экране остаётся. Отступление от раздела 6.2 спецификации, она
    поправлена. Цена: нельзя увидеть пресет на светодиодах до выбора.
26. **Пресет полного заряда при достижении 100% во время зарядки реализован.**
27. **Гашение экраном вверх реализовано.** Переключатель без действия был бы ложью на экране.
    Датчик активен только во время зарядки.

## Решения после проверки на устройстве

28. **Решение 25 отменено: превью пресета на глифе реализовано.** Интерфейс по-прежнему не
    обращается к дисплею. Кнопки превью отправляют идентификатор пресета в singleton-шину
    `PreviewRequestBus`, а запросы разбирает единственный владелец дисплея — оркестратор, на
    общем однопоточном диспетчере вместе с остальными событиями, поэтому двух писателей в SDK
    не возникает. Предпросмотр не подавляется гашением экраном вверх, работает без зарядки,
    новый запрос отменяет прежний, после показа возвращается шкала (при зарядке) или глиф
    гаснет. Запрос без слушателя отбрасывается; при выключенном приложении экран объясняет,
    что на глифе превью видно только при включённом приложении. Раздел 6.2 спецификации
    поправлен.
29. **Параметры каждой анимации (0.2.0).** Модель `AnimationParams` и вся отрисовка — в чистом
    `:core:animation`; выбор зон — одна функция `zonesFor`, ею пользуются и отрисовка, и экран.
    «Регулировать само заполнение» понято как цель (вся полоса или уровень заряда) и стиль
    (плавно или по сегментам). Заполнение по умолчанию теперь плавное, раньше было ступенчатым.
    Яркость анимации хранится как необязательная: пока её не трогали, она следует яркости шкалы,
    поэтому обновление с 0.1.x не меняет яркость анимаций. Превью на глифе по-прежнему передаёт
    только id; параметры оркестратор берёт из сохранённых настроек.
30. **Сессия Glyph отпускается в простое (0.2.1).** Основание — issue #14 Glyph Developer Kit:
    пока открыта сессия стороннего приложения, системный индикатор уведомлений не загорается
    (Phone (2a); на (3a) не проверено). Задержка 2 с выбрана, чтобы быстрое переподключение
    кабеля не открывало сессию заново. Цена: предупреждение о сниженной плавности
    (`STEPPED_ONLY`) видно на главном экране только во время показа, потому что при закрытой
    сессии состояние снова `UNKNOWN`, а каждая новая сессия заново пробует посегментную яркость.
