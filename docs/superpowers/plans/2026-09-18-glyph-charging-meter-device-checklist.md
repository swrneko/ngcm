# Проверка на устройстве — чеклист

Задача 14 плана. Требует Nothing Phone (3a) или (3a) Pro, подключённый по USB.
Всё, что ниже, нельзя проверить тестами: это поведение реального железа, системы и SDK Nothing.

Чеклист собран из ревью всех задач и итогового ревью ветки. Отмечай пункт, записывай
результат, а выясненные факты переноси в раздел «Проверенные факты» спецификации.

## 0. Подготовка

```bash
adb devices
./gradlew :app:installDebug
adb shell getprop ro.product.device
adb shell getprop ro.product.model
adb shell getprop ro.build.version.sdk
```

Запиши модель, версию Nothing OS и уровень API. От уровня API зависит, нужен ли отладочный
режим: он нужен ниже 36.

## 1. Определение модели и доступ

- [ ] `Common.is24111()` возвращает true на 3a и 3a Pro ДО выдачи каких-либо разрешений.
  Если нет — определение модели надо переносить, иначе приложение решит, что телефон не
  поддерживается.
- [ ] На Nothing OS 4.0: онбординг сразу показывает «работает», ни слова про adb.
- [ ] На Android 14/15 без разрешения: онбординг показывает команду.
- [ ] Выдать разрешение и проверить, что приложение само включило флаг:
  ```bash
  adb shell pm grant com.swrneko.glyphmeter android.permission.WRITE_SECURE_SETTINGS
  adb shell settings get global nt_glyph_interface_debug_enable
  ```
  После «Проверить снова» в онбординге вторая команда должна печатать `1`.
- [ ] `register` и `openSession` без отладочного режима на Nothing OS 3.x и 4.0: что именно
  происходит.

## 2. Поканальная яркость — ядро проекта

- [ ] Подключить зарядку. Шкала растёт непрерывно, ведущий сегмент светится частично.
- [ ] В логах нет `per-segment rendering failed`:
  ```bash
  adb logcat -d | grep -i NothingGlyphDisplay
  ```
- [ ] Главный экран не показывает предупреждение о сниженной плавности.
- [ ] Принимает ли глиф яркость выше 4000. Вендорское «полностью включено» в SDK равно 4000,
  верхняя граница диапазона 4095. Есть ли видимая разница.
- [ ] Видно ли сегмент на яркости 800, нижнем пороге видимости.

## 3. Ступенчатый запасной режим

- [ ] Временно принудить `STEPPED_ONLY` в `NothingGlyphDisplay.connect`, пересобрать. При заряде
  около 50% сколько сегментов зажглось. 10 из 20 — аргумент `displayProgress` в диапазоне
  0..100, как в коде. 1–2 — нужен другой масштаб, поправить. Вернуть код.
- [ ] Пресеты WAVE и CHASE в ступенчатом режиме: как выглядят, когда кадр превращается в процент.

## 4. Анимации

- [ ] Каждый из пяти пресетов: заполнение, волна, дыхание, бегущий огонь, вспышка.
- [ ] Проводная зарядка, беспроводная (если есть), отключение — затухание.
- [ ] Пресет полного заряда при достижении 100% во время зарядки, один раз за сеанс.
- [ ] Прирост на полный шаг в режиме «по событию» посреди удержания: шкала перезапускается без
  затемнения. Нет ли мерцания.
- [ ] Пауза зарядки при подключённом кабеле (статус «не заряжается» на 100% или при адаптивной
  зарядке): нет ли ложного затухания и повторной анимации.

## 5. Режимы и настройки

- [ ] Постоянный режим: шкала горит всю зарядку. Нужна ли вообще перерисовка раз в 500 мс —
  есть ли у железа собственный таймаут. Сколько это стоит по батарее.
- [ ] Режим «по событию»: показ, удержание, затухание, повтор при приросте.
- [ ] Гашение экраном вверх: глиф гаснет, когда телефон лежит экраном вверх, и загорается,
  когда переворачиваешь. Пороги датчика 8.0 и 6.0 — подходят ли.
- [ ] Перетаскивание ползунка яркости во время зарядки: глиф не мигает, число следует за пальцем.

## 6. Жизненный цикл и надёжность

- [ ] Первый запуск после установки: сервис стартует сам, без переключения.
- [ ] Отключение зарядки посреди анимации: глиф гаснет и не загорается снова.
- [ ] Десять быстрых переключений выкл/вкл подряд: глиф отвечает, мёртвой сессии нет.
- [ ] `kill -9` процесса, пока глиф горит: гаснет ли глиф, перезапускается ли сервис системой,
  проигрывается ли заново анимация подключения.
- [ ] Обрыв системного сервиса Glyph: приходит ли `onServiceDisconnected`, срабатывает ли
  переподключение, что видит пользователь.
- [ ] Работа из фона: экран заблокирован, приложение свёрнуто, 10 минут на зарядке — шкала
  обновляется.
  ```bash
  adb shell dumpsys activity services com.swrneko.glyphmeter | grep -A5 GlyphMeterService
  ```
  Если система убила сервис — записать как подтверждённое ограничение «только приложения на
  переднем плане». Не обходить молча.
- [ ] Перезагрузка телефона: сервис стартует из приёмника загрузки.
- [ ] Сервис типа `specialUse` и старт из приёмника загрузки на Android 15 и 16: не отклоняет ли
  политика.
- [ ] Уведомление сервиса видно без запроса разрешения на уведомления. Поведение при отказе в
  этом разрешении.

## 7. Сброс отладочного режима через 48 часов

Главный риск, ради которого делалось исправление критической находки итогового ревью.

- [ ] Телефон без перезагрузки больше 48 часов, приложение не открывать. Флаг сбросился?
  Перевзвёл ли его сервис при следующем подключении зарядки?
- [ ] Переживает ли уже открытая сессия сброс флага, или `register` после сброса отказывает.

- [ ] После разрешения приложение само включает флаг.

## После проверки

- Поставить `hardwareVerified = true` у `DeviceLayouts.PHONE_3A`, если раскладка подтвердилась.
- Перенести выясненное в «Проверенные факты» спецификации, убрать из «Непроверенного».
- Если что-то не работает — завести задачу, не чинить вслепую.

## Отпускание сессии (0.2.1)

- [ ] С включённым приложением и без зарядки: системный световой индикатор уведомлений (Essential Notifications) загорается на новое уведомление.
- [ ] В режиме «по событию»: через несколько секунд после того, как шкала погасла, индикатор уведомлений снова работает.
- [ ] Быстрое отключение и подключение кабеля (за 1–2 с) не вызывает ошибок и показывает анимацию.
